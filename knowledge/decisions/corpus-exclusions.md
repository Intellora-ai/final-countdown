# Corpus exclusions and licence constraints

**Date:** 2026-08-29.
**Scope:** which of the twenty requested knowledge sources were mirrored under
`knowledge/`, which were not, and the licence terms that bind the ones that were.

Every source below was checked against the GitHub API — existence, size,
licence, archived status, default branch — and the LICENSE body was read by hand
wherever the SPDX detector returned `NOASSERTION`. None of this is assumed.

---

## Not mirrored

### developer-roadmap — moved, and the licence restricts redistribution

`kamranahmedse/developer-roadmap` no longer exists at that path. The API
redirects to `nilbuild/developer-roadmap` (354 MB). Its licence is custom, not a
standard open one, and it restricts sharing the content "from any other medium
including but not limited to blog".

**Decision: not mirrored.** This repository is public and company-owned, so
unclear redistribution terms are a real risk, not a technicality. The router
references it **by URL only**.

### devdocs — a browser, not a corpus

`freeCodeCamp/devdocs` is MPL-2.0 and 32 MB, so the licence is not the problem.
DevDocs is a **documentation browser**: the documentation itself is scraped at
runtime and is **not in the repository**. Mirroring it would install scrapers and
zero content.

**Decision: not mirrored.** API-reference lookups route to `mdn/content` plus the
current official documentation for whatever is being looked up.

### cs50 — no licence at all

`cs50/lectures` is 395 MB with **no licence file**. No licence means all rights
reserved, not public domain. The rest of the `cs50` organisation is tooling —
`libcs50`, `check50`, `submit50` — which is software, not knowledge.

**Decision: cannot be mirrored.** CS-foundations questions route to `ossu` and
`freeCodeCamp`, both already installed and both properly licensed.

### nand2tetris — an organisation, and the book is not on GitHub

`nand2tetris` is a GitHub organisation, not a repository. Only
`nand2tetris/projects` (<1 MB) was added; `web-ide` (46 MB) is application code,
not teaching material.

**Recorded so the router does not oversell it:** `nand2tetris/projects` is
**exercise skeletons, not explanation**. The textbook that explains the exercises
is not on GitHub and is not in this corpus. Routing a "how does a CPU work"
question here alone will return stubs and no answer.

## Mirrored, with a NonCommercial licence constraint

These **are** in the corpus. The constraint is written here so that it is a
recorded fact rather than something a future session has to remember.

| Source | Path | Licence |
|---|---|---|
| `progit/progit2` | `knowledge/progit` | **CC BY-NC-SA 3.0** |
| 55 OpenStax `osbooks-*` repositories | `knowledge/openstax/*` | **CC BY-NC-SA** (see below) |

**NC means NonCommercial.** The material may be read, studied and adapted for
non-commercial use with attribution and share-alike. It may **not** be
redistributed or reused as part of a commercial product. Treat it as background
reading for engineers, never as content to ship.

Both were mirrored on the owner's explicit decision, made after being shown the
NonCommercial term.

### The OpenStax licence detail

The GitHub licence detector disagrees with the repositories themselves:

- **13 of 55** report `CC-BY-4.0` to the API.
- **42 of 55** report `NOASSERTION` — the detector found no standard licence file.

Reading the `NOASSERTION` repositories' own READMEs shows they state **CC BY-NC-SA**.
So the API answer is not usable, and the safe reading — the one recorded here —
is that the whole OpenStax set carries the **NonCommercial** term. Do not assume
plain CC-BY across all 55 because 13 of them report it.

Each repository's per-repo licence string is carried in `knowledge/README.md`,
which is generated by `scripts/knowledge_manifest.py` and must never be
hand-edited.

## OpenStax is `.cnxml`, not markdown — the search layer must know

OpenStax textbook text is **`.cnxml`**, a custom XML format, one file per module
under `modules/`. It is **not** markdown, and it is not `.xml` either — the
extension is literally `cnxml`.

**Requirement for the search layer:** its file-extension whitelist must include
`cnxml`. A whitelist of the usual `.md`/`.txt`/`.rst` shapes will match **zero**
OpenStax files. That failure is silent and misleading: every OpenStax query
returns nothing, and the corpus looks *empty* when it is really *unsearched* —
2 GB of textbook sitting there, invisible, with no error to explain why.

`scripts/knowledge_search.py` is being written by another agent. This is recorded
here as a requirement on that script, not applied to it. Do not edit that file
from this decision.

## Why OpenStax is most of the disk and almost none of the text

Measured on `knowledge/openstax/anatomy-physiology`, 2026-08-29:

| Thing | Measured |
|---|---|
| Whole checkout | **516 MB** |
| `media/` (images) | **511 MB** |
| `modules/` (the `.cnxml` text) | **5.5 MB** |
| `.cnxml` files | 198 |
| `.jpg` files | 741 |
| `.png` files | 196 |

**Images are 99% of the bytes. The searchable text is 1%.**

This is why `--depth 1` saved so little here, and the reason generalises even
though the percentage does not.

**Shallow cloning drops history and nothing else.** How much that saves is not a
rate to expect; it is decided entirely by whether a given repository's weight
*is* history or is files sitting in the current tree. Measured here:

| Repository | Reported | On disk shallow | What its weight is |
|---|---|---|---|
| `progit` | 183 MB | **21 MB** | history |
| `mdn/content` | 493 MB | **138 MB** | history |
| `openstax/anatomy-physiology` | 487 MB | **516 MB** | current-tree images |

The first two shrank a lot because history was most of what they carried. The
third did not shrink at all — it grew slightly against the reported figure —
because its weight is **binary images in the current tree**, which shallow
cloning cannot touch.

So do not carry a "shallow saves ~N%" figure forward from any of these. Ask the
question that actually decides it: *is this repository heavy with history, or
heavy with files?* Only the first kind is helped by `--depth 1`.

The consequence to expect and not be alarmed by: across the full corpus,
**`openstax/` is roughly 90% of the disk and roughly 2% of the searchable
text.** A future session looking at `du -sh knowledge` and concluding the corpus
is enormous is reading a picture library, not a reading list. The owner was
shown the 9-11 GB figure and approved it.

### The option that exists if the corpus ever needs to shrink

**`git sparse-checkout` excluding `media/` would retrieve the same searchable
text at roughly 1% of the disk.** All the text lives in `modules/`; `media/` is
images the search layer never reads.

Measured across the first 15 OpenStax books to land, 2026-08-29:

| | Measured |
|---|---|
| All 15 books | **3,497 MB** |
| Their `media/` directories | **3,358 MB** — 96% |
| Everything else, text included | **139 MB** — 4% |

Roughly:

```bash
git -C knowledge/openstax/<book> sparse-checkout set --no-cone '/*' '!/media'
```

**This has deliberately NOT been done.** The owner chose full clones knowingly,
after being shown the size. Nothing here reverses that.

It is written down so that a future decision to shrink the corpus starts from a
**measured 96%**, not from a guess. Two things to weigh before acting on it: the
images are part of a textbook and dropping them makes figures unviewable, and
sparse-checkout is per-clone local state, so it would not shrink the repository
for anyone else.

For contrast, and to show that this ratio is specific to OpenStax rather than
general: `progit` reported 183 MB upstream and is **21 MB** on disk, and
`mdn/content` reported 493 MB and is **138 MB**. Those are history-heavy code
repositories, so shallow cloning did the work there and sparse-checkout is not
needed.
